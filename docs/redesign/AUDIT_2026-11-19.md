## Priority 1: privacy and functional defects

**Work in progress:** category isolation, sidebar/Curriculum CGPA controls,
legacy storage migration, zero attendance, Home and sidebar identity, Home
attendance and selected payment surfaces have fixes. A demo browser capture
confirmed attendance-only selection leaves credits visible and covers the Home
attendance values. This is not yet a full coverage or browser verification:
remaining attendance/marks/fees surfaces, peek on touch/keyboard, marker
styling, and actual animation playback still need checks. The numbered items
below are the original findings, not a claim that each is still unfixed.

Further coverage: Academics final grades and secondary score percentages, and
the predictor's header, current and projected course percentages, are now
tagged. Other details and derived values still require a page-by-page privacy
audit; this does not complete coverage.

1. **Category selection does not isolate categories.** `useAppAppearance.ts`
   adds `privacy-mode` whenever the master is on, while `globals.css` uses
   `.privacy-mode [data-private]` to cover all tagged values. Test selecting
   only one category and verify all other categories stay visible, including
   generic `data-private="all"` stats.
2. **Coverage is incomplete.** Home name and photo, sidebar identity,
   attendance details, marks/grades, payment wallet summaries and receipt
   details, and Curriculum subtitles/derived numbers need an inventory. For
   example Curriculum's projected-CGPA subtitle displays `currentCgpa` and
   Payments' receipt `KeyValue` displays the amount without a category tag.
   Test each category on every surface and avoid promising complete screen
   privacy until all relevant values are covered.
3. **Conflicting controls and migration.** Sidebar CGPA click sets
   `privacyMode: false`; Curriculum maintains its own `isCgpaBlurred` state
   and writes the legacy `CGPAHidden` key. The settings storage adapter merges
   defaults before reading, so verify migration of old `CGPAHidden` and
   `blurGrades` blobs against actual storage, not just a partial object.
   Check shortcut, palette, sidebar and settings all agree after reload.
4. **Peek and cover styles need browser tests.** Covered values have
   `visibility: hidden !important`; hover/focus rules do not restore it.
   Check touch, keyboard, marker variants and print in a real browser. Ensure
   the visible cover obscures data without revealing it in adjacent subtitles.
5. **Zero attendance.** Sidebar formatter treats `0` as missing (`<= 0`), so
   verify a real zero is shown as 0% rather than a dash or fallback.
6. **Identity hash endpoint.** `src/lib/posthog.ts` calls
   `/support/identity-hash`; no matching route was found in the local API
   tree. Verify the deployed API contract and fallback before changing it.

The focused tests include a real storage migration check. Add browser-level
regressions for the behaviours above. Full suite 2026-11-19: 15 failing tests,
matching the known baseline (2,753 passed; 8 skipped).

### Initial visual observations (demo, 2026-11-19)

- Home, 390px light: the two-up summary fits and the bottom navigation remains
  readable. Course titles and carousel subtitles truncate; assess whether a
  second line would make the timetable more useful without crowding it. Check
  the whole scroll and overlay clearance before calling the phone view done.
- My Courses & Marks, 1440px: cards and score blocks are legible, but the
  score block repeats the same number as a fraction and a percentage. Consider
  whether both are useful, particularly on phones. The screenshot runner's
  theme selection was inconsistent (the page was light while the sidebar
  indicated Dark), so do not count it as a verified light/dark pass.
- Payments, 1440px dark: the summary, tabs and wallet row are visually clear
  in demo. Financial amounts remain a privacy-coverage priority, and receipt
  detail, empty/error states and phone layout remain unchecked.
- Attendance predictor, demo 390px light and dark: the dark ochre summary
  previously showed a mint percentage; using the explicit highlight variant
  restores ink text (checked in the dark screenshot). Absent-day cells now use
  danger tokens. Demo data had no selectable days, so the absent-day state and
  bottom-bar clearance still need populated-data checks in both themes.
- Student profile status cards: decorative icon tiles were removed and the
  clear-everything button uses semantic danger colours. Demo screenshots were
  checked at desktop light, phone dark, and phone/desktop Night; the full
  three-theme/viewport and real-data matrix remains open. The screenshot runner can report a stale theme
  selection, so confirm the rendered palette before counting a capture.
- During local development, Serwist is disabled yet service-worker registration
  logs a `/sw.js` 404. Confirm production behaviour separately; this is a dev
  observation, not evidence of a production offline defect. The dev compiler
  also reports FFCS PDF-worker circular chunk dependencies; investigate if
  they affect builds or loading before prioritising a fix.
